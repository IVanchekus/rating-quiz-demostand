# Питерский мостик IT Challenge

Telegram-викторина и публичный рейтинг для мероприятий. Полное исходное описание сохранено в [bridge_it_challenge_spec.md](bridge_it_challenge_spec.md).

MVP: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, python-telegram-bot 22, MySQL 8.4, Vue 3 / TypeScript / Vite. API, bot и worker работают отдельными процессами с одним сервисом игры и общей БД. Браузер получает рейтинг через HTTP раз в 15 секунд.

## Быстрый запуск

Нужны Docker с Compose и Python 3 для однократного создания конфигурации.

```sh
python3 scripts/setup_env.py
docker compose up -d --build
docker compose exec api python -m app.seed --demo-room
```

Первый шаг создаёт `.env` с уникальными случайными паролями и ключом администратора; существующий файл сохраняется. Сайт: [http://localhost:8080](http://localhost:8080), кабинет: [http://localhost:8080/admin](http://localhost:8080/admin). Для входа используйте значение `ADMIN_SECRET` из своего `.env`. В браузере ключ хранится только в памяти вкладки, после обновления страницы войдите повторно.

Seed добавляет 4 категории и 16 стартовых вопросов, а `--demo-room` — черновик комнаты. Повторный запуск не дублирует банк. Вымышленные участники и результаты не создаются. Перед мероприятием проверьте вопросы и добавьте собственные задания о компаниях и стенде. Категория «Интерактивные задания» создаётся пустой: такие вопросы зависят от стенда.

В кабинете организатора:

1. Добавьте или отредактируйте вопросы с объяснениями и одним правильным вариантом.
2. Создайте комнату, задайте лимиты и выберите минимум нужное число вопросов.
3. После настройки Telegram нажмите «Запустить». У запущенной комнаты настройки и банк фиксируются.
4. Откройте QR-код и публичный рейтинг по ссылке карточки. Рейтинг показывает только игровую комнату, статистику и QR-код. Для полноэкранного показа используйте F11; кабинет доступен по `/admin`.
5. «Завершить» фиксирует результаты и закрывает оставшиеся вопросы. По дедлайну это происходит автоматически.

## Подключение Telegram

Создайте бота через BotFather. В `.env` задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` (без `@`). Ссылка и QR формируются из username; значение `YourQuizBot` нужно заменить до использования.

```sh
docker compose --profile telegram up -d
```

Бот использует long polling, входящих портов не требует. Команды: `/start room_CODE`, `/start`, `/score`, `/help`. Играть можно только в личном диалоге. Настоящая отправка Telegram требует действительного токена; без него API, рейтинг, кабинет и worker работают самостоятельно. После изменения `.env` пересоздайте сервисы командой выше.

## Как обеспечивается целостность

- После первой попытки каждая следующая комната требует одноразовый допуск организатора. Он разрешает ровно одну новую комнату; вход по старому QR не расходует допуск. Уникальные индексы запрещают дубли вопросов в личном наборе и два ответа на одно задание.
- Сервисы блокируют участника, затем задание через `SELECT FOR UPDATE`. Проверка времени выполняется после получения блокировок; первый ответ и баллы фиксируются одной транзакцией. Повтор возвращает сохранённый результат.
- Следующий вопрос остаётся `pending`, пока участник не нажмёт «Далее». Повторный callback со старого результата восстанавливает текущий вопрос, не продвигая указатель.
- Выдача резервируется в БД токеном с арендой на 60 секунд. Таймер стартует после подтверждения `sendMessage`. Ошибка отправки оставляет вопрос без таймера; после сбоя процесса аренда истекает и `/start` позволяет повторить отправку. При редком сбое между отправкой и записью подтверждения возможно повторное сообщение с тем же заданием; получить второй ответ или повторные баллы невозможно.
- Время вопроса влияет на баллы, но не закрывает вопрос: после `expires_at` кнопки остаются доступными, правильный ответ даёт `rooms.min_correct_points`, неправильный — 0. Строка таймера в Telegram не показывается. Общий срок комнаты строгий: после `rooms.ends_at` ответы недоступны. Worker закрывает комнату и оставшиеся задания; обработчик ответа самостоятельно проверяет срок комнаты.
- Неотправленные уведомления о результате и финале хранятся в БД и повторяются worker. Недоступный Telegram не мешает фиксировать сроки.
- Вопросы, связанные с комнатой или историей прохождения, нельзя менять. В кабинете доступно создание копии для новой редакции. Для правки вопроса в черновике сначала исключите его из банка комнаты.
- Публичный API не выдаёт варианты, правильность, объяснения, Telegram ID или секреты. До завершения теста баллы и место участника возвращаются как `null`, и его баллы не входят в публичную статистику. Бот показывает личную сумму и прогресс.
- Вверху рейтинга только завершившие тест: баллы по убыванию, суммарное время правильных ответов, время регистрации, внутренний ID. Незавершившие идут ниже в порядке регистрации, без баллов и места. Первые три места показаны только в больших карточках, таблица начинается с четвёртого места и включает играющих. Возле ника нет аватара или значка. Все даты UTC; интерфейс использует серверное время для обратного отсчёта.

## Локальная разработка без сборки контейнеров

Нужны Python 3.12+, [uv](https://docs.astral.sh/uv/) и Node.js 20.19+ (или 22+). Сначала запустите отдельную MySQL и задайте `DATABASE_URL` в окружении. `.env` читается из текущей рабочей папки процесса; для backend можно передать абсолютный env-файл через оболочку либо держать локальную конфигурацию в `backend/.env`.

```sh
cd backend
uv sync --frozen
export DATABASE_URL='mysql+pymysql://user:password@127.0.0.1:3306/bridge_quiz?charset=utf8mb4'
uv run alembic upgrade head
uv run python -m app.seed
uv run uvicorn app.main:app --reload
```

В другом терминале:

```sh
cd frontend
npm ci
npm run dev
```

Vite проксирует `/api` на `127.0.0.1:8000`. Команды отдельных процессов из `backend`: `uv run python -m app.bot.main`, `uv run python -m app.worker.expiration`. При запуске без Docker задайте одинаковые переменные подключения всем процессам. Основные запросы описаны в `/docs` на порту API (в Compose этот порт наружу не опубликован).

## Проверки

```sh
cd backend
uv sync --frozen
uv run pytest -q
cd ../frontend
npm ci
npm test
npm run build
```

Быстрые тесты используют временную SQLite; тесты блокировок выполняются только с MySQL. Для полного прогона создайте **отдельную тестовую БД с именем, заканчивающимся на `_test`**:

```sh
cd backend
TEST_DATABASE_URL='mysql+pymysql://user:password@127.0.0.1:3306/bridge_quiz_test?charset=utf8mb4' uv run pytest -q
```

Тесты создают и удаляют таблицы только указанной тестовой БД. Они проверяют двойную регистрацию, конкурентные ответы и «Далее», дедлайны, формулу, доставку, восстановление, запрет изменения истории, порядок рейтинга, авторизацию и отсутствие закрытых данных в публичном API. Сборка frontend включает проверку TypeScript.

## Развёртывание и обслуживание

`docker-compose.yml` запускает MySQL с постоянным volume; одноразовый сервис `migrate` завершает Alembic до старта API, worker и bot. MySQL и API доступны только внутри сети Compose. Nginx раздаёт Vue и проксирует API; на хост по умолчанию опубликован `127.0.0.1:8080`. Укажите `PUBLIC_BASE_URL` и `CORS_ORIGINS` для своего домена. Для публикации используйте HTTPS reverse proxy; при необходимости измените `WEB_BIND_ADDRESS` осознанно.

Для доступа с другого компьютера по IP сервера задайте в `.env` `WEB_BIND_ADDRESS=0.0.0.0`, `PUBLIC_BASE_URL=http://<IP-сервера>:8080` и добавьте этот же адрес в `CORS_ORIGINS`. Примените настройки командой `docker compose up -d --no-deps api frontend`. Открывайте сайт по `http://<IP-сервера>:8080`; публикация MySQL и отдельного порта API для этого не требуется.

Административные запросы требуют `Authorization: Bearer <ADMIN_SECRET>`; секрет минимум 32 символа. API ограничивает частоту запросов по IP (120/мин для admin, 300/мин для public); Nginx добавляет общий лимит 10 запросов/сек. Рассчитано на один процесс API. При масштабировании ограничение частоты нужно перенести на общий gateway. Логи игрового сервиса содержат внутренние ID событий без токенов и личных ответов.

В кабинете `/admin` раздел «Пользователи» показывает сводную активность и открывает карточку с попытками, комнатами, вопросами и ответами. Кнопка «Выдать ещё попытку» требует подтверждения; допуск потратится при первом входе пользователя в новую комнату, а срок прохождения будет равен длительности этой комнаты.

```sh
docker compose ps
docker compose logs --tail=100 api worker
docker compose --profile telegram logs --tail=100 bot
docker compose down
```

`down` сохраняет данные. Не используйте `down -v`, если хотите сохранить игры. Перед изменениями схемы делайте резервную копию MySQL; миграции добавляются отдельными ревизиями. Начальная миграция содержит замороженную схему, независимую от текущих ORM-моделей.

Проект не требует Redis и WebSocket. Процессы PTB, API и worker можно перезапускать независимо. Установка зависимостей воспроизводится по `backend/uv.lock` и `frontend/package-lock.json`.

Для Serena добавлены проектные заметки в `.serena/memories`; их ссылки можно проверить командой `serena memories check` из корня проекта.
